# The API contract

`contracts/` is the single source of truth for HiringPlug's API and its job
messages. The Go server types, the TypeScript client and the Python models are
all generated from it, so the three languages cannot disagree.

```
openapi.base.yaml      shared parts: roles, shared error codes, the Error shape, IDs, money
modules/<module>.yaml  one file per module: its endpoints, schemas, permissions, error codes, jobs
openapi.yaml           GENERATED by `task gen` (merged and checked). Never edit it.
```

## A module file

```yaml
x-module:
  name: notes                      # must match the file name
  description: What the module is for.
  permissions:
    notes:read:                    # must start with the module name
      description: View notes.
      roles: [owner, admin, recruiter, viewer]   # roles that get it by default
    notes.private:read:            # finer-grained, e.g. sensitive fields
      description: View private notes.
      sensitive: true
      roles: [owner, admin]
  errorCodes:
    NOTE_LOCKED: { status: 409, description: Locked notes cannot be edited. }
  jobs:
    note.summarize:                # entity.action
      queue: ai                    # ai = Python worker, core = Go worker
      payload: NoteSummarizeJob    # a schema in this file
      description: Summarize a long note.

paths:
  /v1/notes:
    get:
      operationId: listNotes       # required, unique
      x-permission: notes:read     # required: a declared permission, `authenticated` or `public`
      ...
components:
  schemas: ...
```

## What `task gen` checks while merging

Merging fails, listing every problem at once, if:

- two modules define the same path, schema, permission, error code or job kind;
- a module defines a permission that does not start with its own name;
- an operation lacks `operationId` or `x-permission`, or uses an undeclared permission;
- a permission grants a role that is not in `x-roles`, or a job names a missing schema;
- the result is not valid OpenAPI.

The merge also generates the `Role`, `Permission`, `ErrorCode` and `JobKind`
enums, and summary blocks (`x-permissions`, `x-error-codes`, `x-jobs`) that the
Go code reads at startup, so role permissions and error statuses are declared
only here.

## Conventions

- Field names are camelCase; enum values are snake_case; IDs are `<prefix>_<ulid>`.
- Request bodies use `additionalProperties: false`, so a typo in a field name
  is an error instead of being silently ignored.
- Nullable references are written `allOf: [{ $ref: ... }]` with `nullable: true`.
- Prefer additive changes. Removing or renaming a field breaks clients; do it
  deliberately and say so in the pull request.
